## Prisma 7 on SQLite

| Trap                                                                                                                                                             | Fix                                                                                                                                                                                                                | Done right in                                     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------- |
| Prisma 7 has no URL in `schema.prisma` and no Rust engine: the client needs a driver adapter and the CLI reads the URL from `prisma.config.ts`.                  | One `createPrismaClient(url)` in `src/server/prisma-client.ts`; the generated client lives in `src/generated/prisma` (git-ignored). Do not run `prisma init` or upgrade to Prisma 8.                               | `src/server/prisma-client.ts`, `prisma.config.ts` |
| The generated client is per worktree and nothing regenerates it on merge: a stale client gives "`x` does not exist in type `YWhereUniqueInput`".                 | After pulling or merging anything that touches `prisma/`, run `npx prisma generate` (and `npm run db:migrate` to apply). `npm ci` runs `postinstall` → `prisma generate`.                                          | `package.json` `postinstall`                      |
| SQLite through Prisma has no enums and no CHECK constraints, so "status is one of" and "gross = net + VAT" cannot be declared in the schema.                     | Parse the row with its write schema in `src/domain/rows/` before every write (D27); `tests/schema-columns.test.ts` holds the schemas to `schema.prisma`.                                                           | `src/domain/rows/`                                |
| `prisma migrate dev` refuses in a non-interactive agent shell when a change needs a confirmation (a new NOT NULL column on a table with rows, a dropped column). | Make the column nullable or give it a default, or reset the dev database (`npm run db:reset`) before migrating. Never hand-write migration SQL (`RULES.md`, `AGENTS.md`).                                          |                                                   |
| Tests that need a database must not touch `dev.db`.                                                                                                              | `createTestDb()` copies the migrated template that `tests/global-setup.ts` builds once per run; call `cleanup()` in `afterAll`.                                                                                    | `tests/helpers/test-db.ts`                        |
| Prisma has no `SELECT … FOR UPDATE`; two signings of the last unit can both pass the availability check.                                                         | Do the check and the write inside the `withAudit` transaction and make the write conditional (`updateMany({ where: { id, status: 'available' } })`, then check `count === 1`). The hardening agent tests the race. |                                                   |

## Zod 4

## Next.js 16

| Trap                                                                                                                                             | Fix                                                                                                                                            | Done right in                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| The APIs differ from training data: `params` is a Promise, route contexts are typed with `RouteContext<'/api/…'>`, pages with `PageProps<'/…'>`. | Read `node_modules/next/dist/docs/` for the file convention before writing a page or route; copy the shape of the existing routes.             | `src/app/api/assets/[id]/status/route.ts` |
| Cookies are read-only in a server component: setting the demo clock cookie while rendering throws.                                               | A route handler sets the cookie on its 303 response (`src/app/api/demo/clock/route.ts` when it exists); the page reads it on the next request. | the demo page (wave 0c)                   |
| `next.config.ts` is transpiled without the tsconfig paths: importing a module that uses `@/` fails to load.                                      | Modules that `next.config.ts` imports use relative imports only.                                                                               | `next.config.ts`                          |
| An error thrown in a server component shows a generic message in a production build; only `digest` matches the server log.                       | Words meant for the user belong in the page (a message key), not in a thrown error. The envelope's `fail()` codes are what the UI switches on. | `src/server/api-response.ts`              |
| `next build` or the pre-push hook run while `next dev` is serving can kill the dev server's workers.                                             | Stop the dev server before `npm run check:all` or a push; restart it afterwards.                                                               |                                           |
| The dev server refuses scripts and HMR to any origin but localhost: a phone on the LAN gets a page that never hydrates.                          | `allowedDevOrigins` in `next.config.ts` with the LAN host only when demoing on a phone; `next start` has no such check.                        |                                           |
